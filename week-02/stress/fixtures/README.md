# Заглушки для проверки stress.sh

Это не задачи — это «испытательный стенд» для вашего стресс-тестировщика: маленькие программы с заранее известным поведением, на которых `check.sh` проверяет, что `stress.sh` соответствует спецификации. Читать их можно и нужно — заодно это примеры того, как выглядит генератор и чекер с правильным интерфейсом.

Задача «сумма чисел» (вход: `n`, затем `n` чисел; выход: их сумма):

| Файл | Поведение |
|---|---|
| `gen.py` | генератор: `./gen.py SEED` → `n` от 1 до 10, числа от −100 до 100 |
| `ok.py`, `ok2.py` | два верных решения, написанные по-разному — на них stress.sh обязан молчать |
| `wa.py` | врёт при `n ≥ 7` (теряет последнее число) — должен быть пойман как **WA** |
| `tl.py` | спит 10 секунд при `n == 3` — должен быть пойман как **TL** (с `-t 1`) |
| `re.py` | падает с кодом 3 при `n == 4` — должен быть пойман как **RE** |

Задача «индекс максимума» (вход как выше; выход: любой индекс максимального элемента):

| Файл | Поведение |
|---|---|
| `gen-argmax.py` | генератор с маленькими значениями — максимум часто повторяется |
| `first.py`, `last.py` | оба верны, но печатают разные индексы — без чекера stress.sh будет «ловить WA» на верных ответах |
| `chk.py` | чекер: `chk.py input output answer`, код 0 = принято |

Все файлы — исполняемые скрипты с shebang: stress.sh запускает их как обычные программы, не зная, что внутри Python.
