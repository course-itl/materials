# Шпаргалка bash-скриптов — неделя 2

Справочник: «как», без «почему». Номер главы у раздела — где искать «почему» (`reading/`). Непонятная строка — повод открыть главу, а не скопировать её вслепую. Как из этих кусочков собирается stress.sh шаг за шагом — `stress/guide.md`.

## Скелет скрипта (гл. 1, 3)

```bash
#!/usr/bin/env bash
# имя.sh — одна строка: что делает.
#   имя.sh [опции] АРГУМЕНТЫ         # как запускать
set -u                    # неизвестная переменная = ошибка (а не пустая строка)
# set -euo pipefail       # + падать на первой ошибке; см. гл. 3, когда это уместно

usage() { echo "Использование: $0 GEN A B" >&2; }

main() {
  ...
}
main "$@"
```

```
chmod +x имя.sh           один раз; дальше ./имя.sh
bash имя.sh               запустить без +x (shebang при этом игнорируется)
bash -n имя.sh            только проверить синтаксис
bash -x имя.sh            трассировка: печатать каждую команду перед выполнением
shellcheck имя.sh         линтер; код SC#### → https://www.shellcheck.net/wiki/SC####
```

## Переменные и подстановки (гл. 1)

```bash
NAME=value                # без пробелов вокруг =; всё — строки
echo "$NAME" "${NAME}"    # ${} нужны, когда дальше идут буквы: "${N}th"
export NAME               # видна дочерним процессам (окружение)
readonly N=100            # константа
local x                   # внутри функции: локальная

out=$(команда)            # вывод команды → строка (без завершающего \n)
n=$((a + b * 2))          # целочисленная арифметика; (( i++ )) — тоже
${#s}                     # длина строки;  ${VAR:-default} — значение или default
```

| Переменная | Что это |
|---|---|
| `$0` | имя скрипта |
| `$1`…`$9`, `${10}` | аргументы |
| `$#` | число аргументов |
| `"$@"` | все аргументы, каждый отдельным словом (всегда в кавычках) |
| `$?` | код возврата последней команды |
| `$$` | PID текущего шелла |
| `$SECONDS` | секунд с запуска скрипта |
| `$RANDOM` | случайное 0..32767 |

## Кавычки (гл. 1) — главное правило недели

```bash
"$var"      # ВСЕГДА: без кавычек значение режется по пробелам и раскрывает * ?
'$var'      # одинарные: ничего не раскрывается, буквально $var
"$@"        # все аргументы как есть;   $@ и "$*" — почти всегда ошибка
find . -name '*.py'    # шаблон в кавычках, иначе его раскроет shell, а не find
```

## Условия (гл. 2)

Условие — это команда; истина — код возврата 0.

```bash
if команда; then ...; elif ...; else ...; fi
if [[ "$a" == "$b" ]]; then       # строки: == != ; шаблоны: [[ $f == *.cpp ]]
if [[ "$n" -gt 10 ]]; then        # числа: -eq -ne -lt -le -gt -ge
if [[ -f "$f" ]]; then            # файлы: -f файл -d каталог -x исполняемый -e есть -s непустой
if [[ -z "$s" ]]; then            # -z пустая строка, -n непустая
if ! команда; then                # отрицание
[[ a && b ]]  [[ a || b ]]        # логика внутри [[ ]]
[ "$a" = "$b" ]                   # POSIX-вариант: [ — это программа, пробелы обязательны
команда && при_успехе
команда || при_ошибке
```

## Циклы (гл. 2)

```bash
for x in a b c; do echo "$x"; done
for f in *.cpp; do g++ "$f"; done          # glob безопасен без кавычек
for ((i = 1; i <= n; i++)); do ...; done
for i in $(seq 1 "$n"); do ...; done       # {1..10} — только с литералами
while команда; do ...; done
while read -r line; do ...; done < файл    # построчно; -r — не трогать \
break; continue
```

## case и разбор аргументов (гл. 2)

```bash
case "$x" in
  -h|--help) usage; exit 0 ;;
  *.cpp)     echo "исходник" ;;
  *)         echo "что-то другое" ;;
esac

# getopts: короткие опции с аргументами и без
while getopts ":n:s:t:h" opt; do
  case "$opt" in
    n) N=$OPTARG ;;  s) SEED=$OPTARG ;;  t) TL=$OPTARG ;;
    h) usage; exit 0 ;;
    :) echo "-$OPTARG требует аргумент" >&2; exit 2 ;;
    *) echo "неизвестная опция -$OPTARG" >&2; exit 2 ;;
  esac
done
shift $((OPTIND - 1))     # дальше "$@" — только позиционные аргументы
```

## Функции (гл. 2)

## Надёжность (гл. 3)

```bash
set -u                    # неизвестная переменная — ошибка
set -e                    # первая упавшая команда останавливает скрипт
set -o pipefail           # конвейер падает, если упало любое звено
set -euo pipefail         # всё вместе — стандартная первая строка после shebang
команда || true           # «эта команда имеет право упасть» при set -e

TMP=$(mktemp -d)          # уникальный временный каталог; mktemp — файл
trap 'rm -rf "$TMP"' EXIT # убрать при любом выходе, включая Ctrl+C и exit 1
trap 'echo прервано' INT TERM

timeout 2 ./solve < in    # убить через 2 с; код 124 = не уложились
time ./solve < in         # real (стенные часы) / user / sys
diff a b                  # код 0 — одинаковы, 1 — различаются, 2 — ошибка
diff -q a b               # только вердикт;  -u — формат как в git;  -b -B — игнорировать пробелы/пустые строки
cmp -s a b                # побайтово, молча
diff <(cmd1) <(cmd2)      # сравнить выводы двух команд без временных файлов

echo "сообщение" >&2      # диагностика — в stderr; stdout — только для данных
exit 2                    # код выхода: 0 успех, 1 «нашёл проблему», 2 неверное использование
```

## Отладка (гл. 3)

```bash
bash -n имя.sh            # только разобрать синтаксис, не выполнять
bash -x имя.sh            # печатать каждую команду перед выполнением (строки с +), с подставленными значениями
set -x; ...; set +x       # то же, но только для куска скрипта
echo "seed=$seed rc=$rc" >&2      # зонд: в stderr, чтобы не испортить stdout
./stress.sh ...; echo "код: $?"   # посмотреть код выхода
shellcheck имя.sh         # статический анализ; читать замечания сверху вниз
```

Сообщение `stress.sh: line 17: ...` — номер строки в скрипте, с которой начинать. Кусок скрипта, который «делает не то», выполните руками в терминале по одной команде, глядя на вывод после каждой, как конвейер на прошлой неделе.

## Пишем в bash или в Python? (гл. 3, гл. 4)

Bash — клей между программами: запустить, соединить, сравнить, повторить. Python — когда внутри нужно *считать*: структуры данных, числа с плавающей точкой, разбор форматов, больше ~150 строк. Стресс-тестировщик — клей, значит bash; генератор и чекер — данные, значит Python (или C++). Шпаргалка по Python — `python/python-for-cpp.md`, модель языка — гл. 4.
