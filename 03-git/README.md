# Неделя 3 — Git: шпаргалка

Git запоминает, как выглядела ваша папка в разные моменты, и умеет возвращать любой из них. Две недели вы повторяли `add`, `commit`, `push` как заклинание, и пока ничего не ломалось, этого хватало. Эта шпаргалка на тот момент, когда что-то пошло не так. Сверху одна простая картинка, как git устроен внутри. Под ней команды, собранные по вопросу «что я хочу сделать», и для каждой написано, что она делает с картинкой. Тренажёр с задачами лежит в `tasks.md`, он нужен, чтобы картинка перешла из головы в руки.

## Картинка: альбом, фотографии, стикеры

**Коммит это фотография.** Git фотографирует всю папку целиком, со всеми файлами, какими они были в эту секунду. Не «что поменялось», а вся папка. На обороте фотографии подпись: кто снимал, когда, зачем (это сообщение коммита) и стрелка на предыдущую фотографию. Готовую фотографию поправить нельзя, можно только снять новую.

**Имя фотографии это её отпечаток пальца.** Номеров у фотографий нет. Вместо номера длинный хеш вроде `a1b2c3d`, и он вычисляется из содержимого. Поэтому две одинаковые фотографии получают одно имя, а подменить содержимое, оставив имя, невозможно.

**Репозиторий это альбом.** Папка `.git` и есть альбом, в нём лежат все фотографии. В альбом можно только добавлять. Даже когда вы что-то «удаляете» или «переписываете», старая фотография ещё несколько недель лежит в альбоме, и `git reflog` умеет её найти.

**Ветка это стикер.** Ветка не копия папки. Ветка это бумажный стикер с именем, приклеенный на одну фотографию. Сделали новый коммит, стикер переклеился на новую фотографию. Создать ветку значит приклеить ещё один стикер, поэтому это бесплатно и мгновенно. Удалить ветку значит оторвать стикер, фотографии никуда не деваются.

**HEAD это стикер «вы здесь».** Обычно он приклеен не на фотографию, а на другой стикер, на ветку, и тогда новые коммиты двигают эту ветку. Если приклеить HEAD прямо на фотографию, git скажет «detached HEAD»: вы здесь, но ни один стикер за вами не идёт, и новые фотографии легко потерять.

```
   A ◄── B ◄── C ◄── D
               ▲     ▲
               │     └── fix        (стикер)
               └──────── main ◄── HEAD («вы здесь», приклеен к main)
```

Стрелки смотрят назад: каждая фотография знает своего родителя и не знает детей. Здесь `fix` ушла на одну фотографию вперёд от `main`, а вы стоите на `main`. `git log --oneline --graph --all` рисует ровно эту картинку.

**Три зоны: стол, коробка, альбом.**

```
   стол                  коробка                 альбом
   (рабочая папка,       (индекс, staging,       (репозиторий, .git,
    ваши файлы)           что войдёт в снимок)    все фотографии)

   правите  ──git add──►  складываете  ──git commit──►  фотография
```

Вы работаете на столе. В коробку складываете то, что попадёт на следующую фотографию. `git commit` фотографирует коробку, а не стол. Коробка нужна, чтобы снимать не всё подряд: починили баг и заодно вставили отладочный print, значит, в коробку кладёте только починку. `git status` показывает все три зоны сразу.

**Другие альбомы.** На GitHub лежит ещё один альбом, копия вашего, git зовёт его `origin`. `git push` относит туда ваши фотографии, `git fetch` приносит оттуда чужие. Если альбом чужой и писать в него нельзя, вы делаете **fork**, свою копию на GitHub, а потом открываете **pull request**: «посмотрите мои фотографии и, если всё хорошо, возьмите их к себе».

## Словарик

| Слово | На пальцах |
|---|---|
| commit, коммит | фотография всей папки плюс подпись и стрелка на предыдущую |
| hash, хеш | имя фотографии, посчитанное из её содержимого, вроде `a1b2c3d` |
| repository, репозиторий | альбом, папка `.git` |
| working tree, рабочая папка | стол, файлы, которые вы правите |
| index, staging, индекс | коробка, то, что войдёт в следующую фотографию |
| branch, ветка | стикер с именем на одной фотографии |
| HEAD | стикер «вы здесь» |
| detached HEAD | HEAD приклеен к фотографии, а не к ветке, новые коммиты легко потерять |
| merge | склеить две ветки: фотография с двумя родителями |
| rebase | переснять свои фотографии поверх чужих, чтобы история стала прямой линией |
| conflict, конфликт | обе стороны поменяли одни и те же строки, git спрашивает, как надо |
| remote (`origin`, `upstream`) | другой альбом, обычно на GitHub |
| fork | своя копия чужого альбома на GitHub |
| pull request, PR | просьба «посмотрите мои фотографии и возьмите к себе» |
| reflog | дневник, куда ходил HEAD; спасает почти после всего |
| stash | отложить незаконченное со стола в сторонку |

## Сфотографировать

| Хочу | Команда | Что происходит с картинкой |
|---|---|---|
| положить файл в коробку | `git add файл` | файл со стола копируется в коробку |
| положить только часть правок | `git add -p файл` | git показывает кусочки, вы отвечаете `y` или `n` на каждый |
| сделать фотографию | `git commit -m "stats: survive empty input"` | коробка снимается, стикер ветки и HEAD переезжают на снимок |
| сделать фотографию с длинной подписью | `git commit` | откроется редактор; первая строка заголовок, дальше пояснение |
| переснять последнюю фотографию | `git commit --amend` | старая заменяется новой, только если её ещё никто не видел |
| вынуть файл из коробки | `git restore --staged файл` | в коробке как в последней фотографии, стол не трогается |

Подпись к фотографии пишется по-английски, в настоящем времени, о сути: `stats: survive empty input`, а не `fix` и не `wip`. Один коммит одно изменение, тогда ревьюер читает по коммиту, `revert` откатывает по коммиту, `bisect` ищет виновный коммит.

## Ветки: стикеры

| Хочу | Команда | Что происходит с картинкой |
|---|---|---|
| новый стикер и встать на него | `git switch -c имя` | стикер на текущую фотографию, HEAD на стикер |
| перейти на другой стикер | `git switch имя` | HEAD на стикер, стол перекладывается под него |
| список стикеров | `git branch` | звёздочка там, где HEAD |
| оторвать стикер | `git branch -d имя` | фотографии остаются; `-D`, если git упирается, что ветка не слита |
| переименовать стикер | `git branch -m старое новое` | |
| встать на фотографию без стикера | `git switch --detach a1b2c3d` | detached HEAD; чтобы не потерять коммиты, потом `git switch -c имя` |

## Склеить две ветки

Вы на `main` и хотите забрать работу из `fix`. Способа два, содержимое файлов после обоих одинаковое, различается форма истории.

| Способ | Команда | Форма истории | Когда |
|---|---|---|---|
| merge | `git merge fix` | узел: новая фотография с двумя родителями | ветку уже видели другие |
| rebase | `git switch fix`, затем `git rebase main` | прямая линия: ваши фотографии пересняты поверх `main` | ветка только ваша, ещё не опубликована |
| rebase с уборкой | `git rebase -i main` | в списке можно склеить (`squash`), переименовать (`reword`), выкинуть (`drop`) коммиты | перед тем как открыть PR |

Правило одно: что уже опубликовано, только merge. Что ещё никто не видел, можно перекладывать сколько угодно.

## Конфликт: git спрашивает, а не ругается

Обе стороны поменяли одни и те же строки, и git не знает, чья версия правильная. Вопрос записан прямо в файл:

```
<<<<<<< HEAD
ваша версия
=======
их версия
>>>>>>> fix
```

1. `git status` показывает, какие файлы спорные.
2. Откройте файл и напишите ту версию, которая должна быть. Часто это смесь обеих. Уберите маркеры `<<<<<<<`, `=======`, `>>>>>>>`.
3. Проверьте, что всё работает.
4. `git add файл`.
5. Если это был merge: `git commit`. Если rebase: `git rebase --continue`.

Стало страшно: `git merge --abort` или `git rebase --abort` возвращает всё, как было до попытки.

## Отменить

В альбом можно только добавлять, поэтому «отменить» это несколько разных команд. Выбирайте по тому, где лежит ошибка.

| Где ошибка | Хочу | Команда | Что происходит с картинкой |
|---|---|---|---|
| на столе | вернуть файл как в коробке | `git restore файл` | стол ← коробка; правки пропадают насовсем |
| в коробке | вынуть из коробки | `git restore --staged файл` | коробка ← фотография, стол не трогается |
| в коробке и на столе | вернуть файл целиком | `git restore --staged --worktree файл` | и коробка, и стол ← фотография |
| в последних коммитах, ещё не пушили | убрать коммит, правки оставить на столе | `git reset HEAD~1` | стикер назад на одну фотографию, файлы остаются на столе |
| в последних коммитах, ещё не пушили | убрать коммит вместе с правками | `git reset --hard HEAD~1` | стикер, коробка и стол назад; правки со стола пропадают |
| в коммите, который уже видели другие | отменить его честно | `git revert a1b2c3d` | новая фотография, в которой изменения сделаны наоборот |
| файл удалён коммитом | достать из старой фотографии | `git restore --source=a1b2c3d^ -- файл` | файл из родителя того коммита снова на столе |
| всё пропало после `reset --hard` | найти, где был HEAD | `git reflog`, потом `git reset --hard HEAD@{2}` | стикер возвращается на старое место |
| оторвал нужный стикер | приклеить обратно | `git reflog`, потом `git branch имя a1b2c3d` | стикер снова на фотографии |
| нужно срочно отвлечься | убрать стол в сторонку | `git stash`, потом `git stash pop` | стол чист, потом правки возвращаются; `-u` берёт и новые файлы |

`reset` и `revert` путают чаще всего. `reset` переклеивает стикер назад, будто коммитов не было, и годится только для того, чего ещё никто не видел. `revert` делает новый коммит наоборот, и так откатывают то, что уже в `main`.

## Другие альбомы: origin и upstream

| Хочу | Команда | Что происходит с картинкой |
|---|---|---|
| скопировать альбом с GitHub | `git clone git@github.com:кто/что.git` | свой альбом, плюс стикеры `origin/*` показывают, где стоит сервер |
| узнать, что нового на сервере | `git fetch` | новые фотографии приехали, стикеры `origin/*` переехали, ваши стикеры не тронуты |
| забрать и влить в свою ветку | `git pull` | `fetch` плюс `merge` одной командой |
| отправить ветку первый раз | `git push -u origin ветка` | фотографии на сервер, ветка запоминает, что следит за `origin/ветка` |
| отправить ещё раз | `git push` | |
| отправить после rebase | `git push --force-with-lease` | сервер меняет старые фотографии на новые; откажется, если туда успел запушить кто-то ещё |
| добавить оригинал к своему fork | `git remote add upstream git@github.com:course-itl/toolbox.git` | `origin` ваш fork, `upstream` оригинал |
| забрать чужой PR, чтобы запустить | `git fetch upstream pull/42/head:pr-42`, затем `git switch pr-42` | ветка PR у вас на столе |

## Pull request от начала до конца

Так сдаётся всё с этой недели, и так работают в любой команде.

1. **Fork.** На странице `course-itl/toolbox` кнопка Fork. Появляется `<логин>/toolbox`, в него писать можно.
2. **Клон и второй альбом.**
   ```bash
   git clone git@github.com:<логин>/toolbox.git && cd toolbox
   git remote add upstream git@github.com:course-itl/toolbox.git
   ```
3. **Ветка.** `git switch -c add-<логин>`. В `main` руками не коммитят.
4. **Коммиты.** Один коммит одно изменение, подпись по-английски о сути.
5. **Push и PR.** `git push -u origin add-<логин>`, git напечатает ссылку, по ней открыть PR с base `course-itl/toolbox`, ветка `main`. В описании что это, как запустить, на что смотреть ревьюеру.
6. **Ревью.** Ревьюер читает по `review-checklist.md`, вешает комментарии на строки, ставит Approve или Request changes.
7. **Правки.** Новыми коммитами в той же ветке, не `--amend`, чтобы ревьюер видел разницу. `git push`, ответить на каждый комментарий, нажать Re-request review.
8. **`main` уехал, пока вы ждали.**
   ```bash
   git fetch upstream
   git rebase upstream/main      # конфликт → поправить файл, git add, git rebase --continue
   git push --force-with-lease
   ```
9. **Merge.** После Approve кнопка Merge pull request.
10. **Догнать `main` у себя.** `git switch main`, `git pull upstream main`, `git push origin main`, `git branch -d add-<логин>`.

В своём hw-репозитории то же самое, только без fork и upstream: ветка `03-git`, PR в `main`, после Approve кнопка Merge, потом `git switch main`, `git pull`, `git branch -d 03-git`.

## Если всё сломалось

| Git говорит или вы видите | Что это значит | Что делать |
|---|---|---|
| `You are in 'detached HEAD' state` | HEAD на фотографии без стикера | работать можно; чтобы не потерять коммиты, `git switch -c имя` |
| `CONFLICT (content): Merge conflict in ...` | git спрашивает, как склеить строки | раздел «Конфликт» выше |
| `! [rejected] ... (fetch first)` | на сервере есть фотографии, которых нет у вас | `git pull --rebase`, потом `git push` |
| `! [rejected] ... (non-fast-forward)` после rebase | вы пересняли фотографии, сервер хранит старые | `git push --force-with-lease` в свою ветку; в `main` никогда |
| `Your branch is behind 'origin/main'` | на сервере новее | `git pull` |
| `Please commit your changes or stash them before you switch branches` | на столе правки, которые switch затёр бы | `git stash`, переключиться, `git stash pop`; или сначала закоммитить |
| `nothing to commit, working tree clean` | стол и коробка совпадают с фотографией | всё хорошо |
| сделал `reset --hard`, всё пропало | стикер уехал, фотографии ещё в альбоме | `git reflog`, найти хеш, `git reset --hard хеш` |
| удалил ветку, а она была нужна | оторвали стикер | `git reflog`, `git branch имя хеш` |
| закоммитил не на той ветке | стикер не тот | `git switch -c правильная`, вернуться на старую, `git reset --hard HEAD~1` (если ещё не пушили) |
| закоммитил пароль или ключ | если запушили, он в альбоме у всех навсегда | сменить секрет; если не пушили, `git reset HEAD~1` и переделать коммит |
| `git status` завален `out/`, `__pycache__/`, `a.out` | git видит мусор | строки `out/`, `__pycache__/`, `*.o`, `a.out`, `.DS_Store` в `.gitignore`; уже закоммиченный мусор убрать через `git rm --cached файл` |
| открылся vim, не знаю, как выйти | git ждёт подпись к фотографии | `Esc`, `:q!`, Enter; потом `git config --global core.editor nano` |
| тренажёр сломан безнадёжно | | `bash setup.sh --reset` |

- B5, git-гольф: по распечатке `git log --graph` собрать такую же историю в пустом репозитории за минимум команд.

## Правила недели

- `git push --force` в `main` не делает никто и никогда. `--force-with-lease` только в свою ветку своего PR, после rebase.
- Застряли: сначала `git status` целиком, там почти всегда написано, что делать. Потом `git reflog`. Потом сосед, потом преподаватель.
- Подписи к коммитам по-английски, в настоящем времени, о сути: `stats: survive empty input`, а не `fix` и не `wip`.
