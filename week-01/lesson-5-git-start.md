# Урок 5: GitHub и первый коммит

Сегодня — только механика по шпаргалке, без понимания «как git устроен внутри»: этому целиком посвящены недели 3–4. Задача на урок: ваш репозиторий в организации курса существует, в нём лежит результат недели 1, и вы умеете это повторить.

## 1. Вступление в организацию

1. Зарегистрируйтесь на github.com (если аккаунта нет). Логин выбирайте так, чтобы не стыдно было показать работодателю — этот аккаунт станет вашим портфолио.
2. Проверьте почту: там приглашение в организацию `course-itl`. Примите его.
3. В организации уже создан ваш личный репозиторий `hw-<фамилия>`. Весь год сдаёте работы туда.

## 2. Ключ для GitHub

Используем тот же ключ, что и для сервера курса (`setup/ssh-guide.md`):

```bash
cat ~/.ssh/id_ed25519.pub
```

Скопируйте вывод целиком → github.com → Settings → SSH and GPG keys → New SSH key → вставить → Add.

Проверка:

```bash
ssh -T git@github.com
# "Hi <логин>! You've successfully authenticated..." — значит, работает
```

## 3. Представиться git-у (один раз на машину)

Эти имя и почта попадут в каждый ваш коммит:

```bash
git config --global user.name "Имя Фамилия"
git config --global user.email "вы@example.com"   # та же почта, что на GitHub
git config --global init.defaultBranch main
```

## 4. Клонировать свой репозиторий

```bash
cd ~
git clone git@github.com:course-itl/hw-<фамилия>.git
cd hw-<фамилия>
```

## 5. Первый коммит: результаты недели 1

```bash
mkdir -p week-01/solutions
cp ~/quest/FLAG.txt ~/quest/journal.txt week-01/
cp путь/к/вашим/task*.sh week-01/solutions/

git status                  # посмотреть, что git видит как новое
git add week-01
git status                  # файлы позеленели — попали в «корзину» коммита
git commit -m "week-01: quest flag and pipe one-liners"
git push
```

Откройте свой репозиторий на github.com и убедитесь, что файлы там. Это и есть сдача.

## 6. Мини-словарь (пока без глубины)

- **репозиторий** — каталог, историю которого git отслеживает;
- **коммит** — зафиксированный снимок файлов с подписью и сообщением;
- **add** — отобрать, что войдёт в следующий коммит;
- **push** — отправить локальные коммиты на GitHub.

Почему это работает именно так, что такое ветки и как жить при конфликтах — недели 3–4. До тех пор цикл один: `status → add → commit → push` после каждого осмысленного куска работы. Сообщения коммитов — по-английски, в настоящем времени, о сути: `week-01: add task07 solution`, а не `fix` и не `ааааа наконец работает` (хотя все мы там были).
