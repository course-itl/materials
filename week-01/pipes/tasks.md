# Однострочники: вопросы к данным

Перед вами лог веб-сервера за сутки (~100 000 запросов) и дерево исходников. Настоящая работа с такими данными выглядит так: возник вопрос — за 30 секунд собрал конвейер — получил ответ — забыл конвейер. Программа на C++ или Python здесь проигрывает по времени в разы. Цель задач — поставить руку именно на это.

Теория, на которой всё стоит (потоки, редиректы, почему `sort` перед `uniq`, почему конвейер не ест память), — глава 4 учебника. Задачи можно решать и до неё, но после неё они превращаются из подбора заклинаний в конструктор.

## Метод: конвейер наращивают, а не пишут

Прежде чем решать — как решать. Конвейер из пяти звеньев не пишут целиком и вслепую; его выращивают, проверяя каждое звено:

```bash
head -3 access.log                     # шаг 0: СМОТРИМ на данные. Всегда сначала глаза
cut -d' ' -f1 access.log | head        # шаг 1: вырезали первое поле. Похоже на IP? Да
cut -d' ' -f1 access.log | sort | head # шаг 2: отсортировали (одинаковые IP встали рядом)
cut -d' ' -f1 access.log | sort | uniq -c | head          # шаг 3: посчитали повторы
cut -d' ' -f1 access.log | sort | uniq -c | sort -rn | head -5   # шаг 4: топ-5. Готово
```

После каждого шага — взгляд на вывод: ожидаемо? двигаемся дальше; нет? чиним последнее звено, пока оно последнее и всё видно. `| head` на конце — ваш лучший друг: показывает форму данных, не заливая экран.

Этот цикл «посмотрел → добавил звено → проверил» — и есть навык, который сдаётся на этой неделе. Задачи ниже намеренно решаются одним и тем же методом, а не десятью разными трюками.

## Данные

Сгенерируйте свои (у каждого — собственная версия, зависящая от логина):

```bash
bash make-logs.sh          # создаст access.log и code/ в текущем каталоге
```

Формат строки лога (классический формат access.log веб-серверов):

```
203.0.113.7 - - [01/Sep/2026:14:03:27 +0300] "GET /index.html HTTP/1.1" 200 4523 "https://google.com/" "Mozilla/5.0 ..."
```

Если резать строку по пробелам, то: поле 1 — IP, поле 7 — путь, поле 9 — код ответа, поле 10 — размер ответа в байтах. Проверьте сами: `head -1 access.log | tr ' ' '\n' | head -12`.

## Правила

1. Каждое решение — **один конвейер** в отдельном файле `solutions/taskNN.sh` (одна логическая строка; `\` для переноса — можно).
2. Разрешены стандартные текстовые утилиты: `cat, head, tail, wc, grep, sort, uniq, cut, tr, awk, sed, find, xargs`. **Запрещены** python/perl и временные файлы — весь смысл в конвейере.
3. `awk` разрешён, но однострочный (паттерн-действие, без написания «программы на awk» — для неё есть bonus).
4. Файлы решений — обычный текст в кодировке UTF-8 без BOM и с переносами строк LF, как делает любой редактор в Linux и macOS. Редактор в Windows (Блокнот, иногда VS Code) может сохранить файл с BOM в начале или с переносами CRLF; bash увидит в нём невидимые символы и скажет «command not found» про команду, которая точно есть. Проверка такое распознаёт и подскажет, как починить; посмотреть формат файла можно командой `file solutions/task01.sh`.
5. Формат вывода в каждой задаче указан точно — автопроверка сравнивает вывод побайтово. Это не придирка, а первое знакомство с реальностью: автоматике (тестам, CI, другой программе в конвейере) нельзя ответить «ну почти правильно». Машина читает формат, а не намерение.

## Задачи (core: 01–06)

### task01 — размер выборки
Сколько всего запросов в логе? Вывод: одно число.

### task02 — не найдено
Сколько запросов завершилось кодом 404? Вывод: одно число.

### task03 — самые активные клиенты
Топ-5 IP-адресов по числу запросов. Вывод: 5 строк вида `<число> <ip>`, по убыванию числа, разделитель — один пробел.

Подсказка про идиому: `sort | uniq -c | sort -rn | head` — но `uniq -c` добавляет отступы, а нужен ровно один пробел. Приведение к формату — тоже часть задачи (например, финальным `awk '{print $1, $2}'`).

### task04 — самая популярная страница
Какой путь запрашивали чаще всего? Вывод: одна строка — только сам путь.

### task05 — трафик
Суммарный размер всех ответов в байтах. Вывод: одно число.

### task06 — аудитория
Сколько уникальных IP-адресов заходило на сервер? Вывод: одно число.

### task07 — сводка по кодам (доп.)
Все коды ответа с количеством запросов на каждый. Вывод: строки вида `<код> <число>`, отсортированные по коду по возрастанию, разделитель — один пробел.

### task08 — строки кода (доп.)
Суммарное число строк во всех `*.py`-файлах внутри `code/` (на любой глубине). Вывод: одно число.

## Проверка

Локально смотрите на вывод глазами. Автопроверка — на сервере курса (после урока 4). Скопируйте `solutions/` на сервер (`scp -r solutions course:week-01/`) или работайте там сразу (`setup/server-guide.md`), перейдите в каталог, где лежит `solutions/`, и запустите

```bash
check-pipes
```

Команда ищет `solutions/` в текущем каталоге, затем в `~/hw-<логин>/week-01`, затем в `~/week-01`; можно и указать путь явно. Скрипт прогонит ваши решения на канонической версии ваших данных и покажет табличку ✓/✗. Зачёт core = task01–06 зелёные. Проверка сверяет **результат**, а не текст команды: любой корректный конвейер зачтётся.

## Bonus (не автопроверяется, показать на уроке 5)

- **b1, классика:** топ-10 самых частых слов в «Войне и мире». Текст: `curl -L https://www.gutenberg.org/files/2600/2600-0.txt -o war.txt` (это английский перевод — тем проще с кодировками). Слово = максимальная последовательность букв, регистр не важен. Подсказка: `tr -cs 'A-Za-z' '\n'`.
- **b2, картинка из цифр:** почасовая гистограмма запросов: 24 строки `<час> <число>`. А теперь дорисуйте к каждой строке столбик из `#` пропорциональной длины (можно вторым конвейером или awk).
- **b3, превью awk:** средний размер ответа для каждого кода: строки `<код> <средний размер>`. Здесь awk-программа с массивом уже честно уместна — почувствуйте границу, где однострочник перестаёт быть удобным.
- **b4, для дома:** конвейер, отвечающий на любой ВАШ вопрос к этому логу, который мы не задали. Самый интересный вопрос группы разберём на уроке 5.
