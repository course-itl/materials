# SSH на сервер курса

У курса есть общий Linux-сервер. На нём: единое окружение (одинаковое у всех, в отличие от ваших ноутбуков), автопроверка заданий, позже — профилирование (нед. 7) и деплой ваших сервисов (3-я четверть). Логин вам выдаёт преподаватель на уроке 4.

Адрес сервера: `89.169.167.34`.

## 1. Ключи вместо паролей

SSH-ключ — это пара файлов: приватный (лежит у вас, никому не показывается **никогда**) и публичный (раздаётся серверам). Сервер пускает того, кто докажет владение приватным ключом.

Сгенерируйте пару (если уже есть — второй раз не нужно):

```bash
ssh-keygen -t ed25519 -C "вашлогин@курс"
# Enter на все вопросы (путь по умолчанию, без passphrase — пока что)
```

Появятся два файла:

- `~/.ssh/id_ed25519` — **приватный**. Не копировать, не пересылать, не коммитить.
- `~/.ssh/id_ed25519.pub` — публичный. Его содержимое отправьте преподавателю:

```bash
cat ~/.ssh/id_ed25519.pub
```

Этот же ключ вы на уроке 5 добавите в GitHub — один ключ обслуживает всё.

Если вы на WSL2: генерируйте ключ в терминале Ubuntu (чтобы он лёг в `/home/вы/.ssh`, а не в Windows-каталог) — иначе ssh будет ругаться на права файла.

## 2. Конфиг, чтобы не печатать адрес каждый раз

Допишите в файл `~/.ssh/config` (создайте, если нет):

```
Host course
    HostName 89.169.167.34
    User вашлогин
    ServerAliveInterval 60
```

Теперь вход — просто:

```bash
ssh course
```

При первом подключении ssh спросит про fingerprint хоста — ответьте `yes` (он запомнит сервер и дальше будет молча проверять, что это тот же сервер).

## 3. Копирование файлов: scp

```bash
scp solution.cpp course:week-01/      # с ноутбука на сервер
scp course:week-01/result.txt .       # с сервера на ноутбук
scp -r mydir course:                  # каталог целиком
```

Пути справа от `course:` — относительно вашего домашнего каталога на сервере.

## 4. tmux: сессия, которая не умирает

Проблема: закрыли ноутбук / отвалился Wi-Fi → SSH-сессия оборвалась → всё, что в ней работало, убито. Решение — tmux: терминальная сессия живёт **на сервере**, вы к ней лишь подключаетесь.

Минимум для жизни:

```bash
tmux                # новая сессия (на сервере, после ssh)
# ... работаете ...
# Ctrl+b, затем d   # отцепиться (сессия продолжает жить)
tmux attach         # прицепиться обратно (хоть завтра, хоть с другого устройства)
tmux ls             # список сессий
```

Привычка курса: зашли по ssh → сразу `tmux attach || tmux`.

## 5. Правила общежития

Сервер общий, на нём вся группа:

- Домашний каталог — ваш; чужие смотреть можно только если вас позвали.
- Не запускайте бесконечные циклы вне лаб по профилированию; заметили, что сервер тормозит — `htop`, найдите виновника (может, это вы).
- Сервер — часть курса, а не полигон для взлома. Найденную дыру в настройке несите преподавателю — это плюс в карму, а не повод для шалостей.
