# Глава 2 — Файловая система: территория

Терминал всегда «находится» где-то: у каждой команды есть текущий каталог, от которого она отсчитывает пути. В квесте вы будете часами ползать по дереву каталогов, искать спрятанное и чинить права. Эта глава — карта местности и правила передвижения по ней.

## Всё растёт из одного корня

В Unix нет дисков `C:` и `D:`. Есть **одно дерево**, и растёт оно из корня — каталога с именем `/`. Всё остальное — ветви: каталоги внутри каталогов, и на концах — файлы. Флешки, вторые диски, сетевые папки не появляются отдельными буквами — они «прививаются» (монтируются) в ветви этого же дерева.

**Путь** — это маршрут по дереву. Он бывает двух видов, и разница между ними — источник половины ошибок первой недели:

- **Абсолютный** начинается с `/` и описывает маршрут от корня: `/home/vasya/quest/storage`. Работает откуда угодно.
- **Относительный** начинается с чего угодно, кроме `/`, и отсчитывается от **текущего каталога**: `quest/storage` означает «в текущем каталоге найди `quest`, в нём — `storage`». Работает только если вы стоите в правильном месте.

Три специальных имени, которые понимает каждый уголок системы:

- `.` — текущий каталог (пригодится: `./script.sh` — «запусти скрипт отсюда»);
- `..` — каталог на уровень выше (`cd ..` — шаг к корню);
- `~` — ваш **домашний каталог**: личная территория пользователя, `/home/логин` на Linux (на macOS — `/Users/логин`). `cd` без аргументов везёт домой.

Кто «стоит» в текущем каталоге? Не терминал и не вы — а процесс вашего шелла (вспомните главу 1: текущий каталог — свойство процесса). `pwd` спрашивает у шелла, где он; `cd` просит его перейти.

**Попробуйте прямо сейчас:** `cd /` → `pwd` → `ls` → `cd` → `pwd`. Вы сходили к корню, осмотрелись и вернулись домой.

## Краткая экскурсия по дереву

Запоминать не нужно — нужно узнавать в лицо:

| Каталог | Что там |
|---|---|
| `/home` | дома пользователей (`/Users` на macOS) |
| `/bin`, `/usr/bin` | программы — те самые файлы, которые находит `PATH` |
| `/etc` | конфигурация системы, текстовые файлы (загляните: `cat /etc/hostname`) |
| `/tmp` | свалка для временного; может очищаться при перезагрузке |
| `/dev` | «устройства» — о них через абзац |
| `/var/log` | журналы системы — с такими мы работаем на уроке 4 |

## «Всё — файл»

Первый пункт философии Unix, и он буквальнее, чем кажется.

Каталог — это файл (со списком имён). Диск — файл. Терминал, в котором вы сидите, — файл (`/dev/tty`). Генератор случайных чисел — файл (`/dev/random`, попробуйте: `head -c 8 /dev/random | xxd`). Есть даже файл-чёрная дыра — `/dev/null`: всё записанное в него исчезает. Вы его уже видели в демо: `2>/dev/null` — «ошибки выброси».

Зачем такая уравниловка? Чтобы **один набор операций** — открыть, прочитать, записать, закрыть — работал со всем на свете. Программа `wc` считает строки; ей неважно, читает она файл с диска, вывод другой программы или поток с клавиатуры — для неё всё выглядит одинаково. Программы не обязаны знать, с чем имеют дело, — поэтому их можно соединять как угодно. Эта идея выстрелит в полную силу в главе 4: конвейеры возможны именно потому, что всё — файл.

## Скрытые файлы: точка вместо занавески

Правило простое: имя начинается с точки → `ls` по умолчанию его не показывает. Показать всё: `ls -a`.

Это **не защита и не секретность** — любой, кто знает про `-a`, видит всё. Это вежливость: служебные файлы и конфиги (`~/.ssh`, `~/.bashrc`, `~/.gitconfig`) не мельтешат перед глазами, когда вы ищете свои рабочие файлы. Загляните к себе: `ls -a ~` — вы удивитесь, сколько программ уже свили гнездо у вас дома.

Исторический анекдот: это вообще случайность. Авторы раннего Unix хотели спрятать из листинга только служебные `.` и `..`, написали проверку «первый символ — точка? пропустить» — и нечаянно создали механизм скрытых файлов, которым мир пользуется шестой десяток лет.

## Права: правила общежития

Unix с рождения — многопользовательская система: на одной машине работали десятки людей, и нужно было как-то не дать им читать чужую почту и удалять чужие файлы. Права — это и есть правила общежития. На сервере курса, где будет вся группа, вы почувствуете их на себе.

Читаем вывод `ls -l`:

```
-rwxr-xr--  1 vasya students  512  1 Sep 12:00 script.sh
```

Первый символ — тип (`-` файл, `d` каталог). Дальше — три тройки прав для трёх категорий: **владелец** (`rwx`), **группа** (`r-x`), **все остальные** (`r--`). В каждой тройке: `r` — читать, `w` — писать, `x` — исполнять; дефис — права нет.

То есть эту строку человек читает так: «файл; Вася может всё; группа students — читать и запускать; остальные — только читать».

Что важно про `x`:

- Файл без `x` нельзя запустить, даже свой: `./script.sh` → `Permission denied`. Лечится: `chmod +x script.sh`. Свежесозданные файлы исполняемыми **не** рождаются — это осознанно.
- У каталога `x` означает «право войти» — отдельная от чтения вещь; пока просто знайте, что такое бывает.

Менять права может владелец файла (и суперпользователь `root`). Отсюда сюжет, который встретится в квесте: файл ваш, но прав на чтение нет — казалось бы, тупик. Но раз файл ваш, вы вправе вернуть себе права: `chmod +r файл`. «Permission denied» — не стена, а вопрос: *чей это файл и кто может изменить правила?* Ответ всегда начинается с `ls -l`.

## Два поисковика: find и grep

Когда файлов сто пятьдесят, «посмотреть глазами» перестаёт быть стратегией. В Unix два поисковых инструмента, и важно понимать, чем они отличаются: **`find` ищет по свойствам файла, `grep` — по содержимому**.

**`find`** обходит поддерево и печатает то, что прошло фильтры. Схема: `find где какие-условия`.

```bash
find ~/quest -name '*.txt'     # по имени (шаблон в кавычках — почему, узнаем в главе 4)
find ~/quest -size 1337c       # по размеру: ровно 1337 байт (c = байты)
find ~/quest -type d           # только каталоги
```

Условия можно комбинировать — тогда «покажи файлы, такие что…» превращается в маленький язык запросов к дереву.

**`grep`** читает содержимое и печатает строки, где встретилась искомая подстрока. С флагом `-r` — рекурсивно по целому каталогу:

```bash
grep -r 'кодовая' ~/quest/library    # в каком файле упоминается слово?
grep -n 'error' app.log              # с номерами строк
```

Тест на понимание: «найди файл размером ровно 1337 байт» — это про свойство, значит `find`. «Найди файл, внутри которого слово „кодовая“» — про содержимое, значит `grep`. Если держать это разделение в голове, вы никогда не зависнете над вопросом «чем искать».
