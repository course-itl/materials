# Неделя 1 — Linux и терминал: дом разработчика

Ближайшие годы почти всё, что вы делаете с компьютером как разработчики, будет происходить в терминале Unix-системы. На этой неделе мы поселяемся в нём: файловая система, процессы, конвейеры, удалённый сервер. В конце недели у каждого — рабочее окружение, доступ на сервер курса, пройденный терминальный квест и набор конвейеров, решающих настоящие задачи про данные.

## План недели

| Урок | Что происходит |
|---|---|
| 1 | Лекция: как устроен курс; почему индустрия живёт на Unix; анатомия команды (stdin/stdout/stderr, флаги, exit-коды) |
| 2–3 | Лаба: доводим окружение (`setup/check-env.sh` должен быть зелёным у всех); терминальный квест (`quest/`) |
| 4 | Лаба: пайпы и редиректы на настоящих данных (`pipes/`); SSH на сервер курса (`setup/ssh-guide.md`) |
| 5 | GitHub-организация, git config, первый коммит (`lesson-5-git-start.md`); планирование самостоятельной недели |

## Что сдаётся (core — обязательный минимум)

1. **Окружение**: `setup/check-env.sh` проходит без ошибок на вашей машине.
2. **Квест**: файл `FLAG.txt` с флагом + `journal.txt` с ключевыми командами (по одной на шаг). Подробности — `quest/quest.md`.
3. **Однострочники**: задачи 01–06 из `pipes/tasks.md`, автопроверка `check.sh` на сервере курса зелёная.
4. **Первый коммит**: всё перечисленное лежит в вашем репозитории в организации курса, в каталоге `week-01/`.

Структура вашего репозитория после сдачи:

```
week-01/
├── FLAG.txt
├── journal.txt
└── solutions/
    ├── task01.sh
    ├── ...
    └── task06.sh
```

## Правила недели

- Всё делается в терминале. Графический файловый менеджер и IDE на этой неделе — читерство.
- Застряли на 15+ минут — сначала `man`, потом сосед, потом преподаватель. Вопрос «какой командой это делается» — легален всегда; вопрос «где лежит флаг» — нет.
